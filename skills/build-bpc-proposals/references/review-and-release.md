# Review and release

Review the actual candidate against the current request and guidebook. Use pass, revise, pending or not applicable with reasons. There is no universal winning score or compulsory prototype level; a critical error cannot be averaged away.

| Pass | Questions | Evidence |
|---|---|---|
| Rules | Correct scope, structure, eligibility, length, anonymity and format? | Actual guidebook locations and rendered count |
| Business | Can a reader explain purchase, choice, revenue, fulfillment, repeat use and growth? | Continuous body with appendices closed |
| Voice | Confident design, connected paragraphs, interpreted finance? | Actual passages and contextual voice review |
| Claims | Accurate evidence scope and achievement states? | Original locators, actual records and matching references |
| Arithmetic | Demand, capacity, revenue, profit, cash and funding reconcile? | Separate reconstruction against canonical results |
| Operations | Who pays/performs work and handles exceptions as volume grows? | Resources, QC, failure paths and cost steps |
| Document | Exact exported file readable and navigable? | Every rendered page and native DOCX/PDF checks |

Use independent reviewers for bounded questions when available and authorized. Otherwise perform distinct self-review passes and state that limitation. Never label self-review independent or a synthetic exercise a customer test.

Repair false claims, arithmetic, explicit rule failures and privacy defects first. Then repair missing commercial bridges, misleading comparisons, navigation, wording and layout. Preserve protected decisions. Recheck affected dependencies: price changes alter tables, chart series and prose; a paragraph edit can change pagination; a lexical replacement can damage an unrelated name.

## Toolkit release gate

Run applicable tests and `studio.py check`. Exercise the CLI from an unrelated relocated directory containing spaces. Create a fresh project and verify blank venture/numerical fields. Build a representative complete proposal, compile actual current chart inputs, render every sample page, inspect native tables and figures, test body/index/appendix returns, and independently reconcile arithmetic across outputs. Test guidance on a fresh bounded task with its actual rules; do not hint the expected answer to an independent reader.

Check active instructions/links/paths, source hashes and identities, reading coverage and exact gaps, financial limits, final ZIP contents and exclusions. Preserve supplied references and attribution without inventing a blanket license. Inspect the ZIP itself, not only the staging folder. Historical validation is not evidence for this adaptation.

Record each actual command/method, artifact version/hash, result, observation, limitation and repair. Availability, execution, visual layout, economics and demand are separate claims. Update latest artifacts, accepted/protected choices, canonical numbers, sources, assumptions, open issues and next action. Local production does not authorize publishing, submission, partner contact or personal-skill installation.
