# BPC Studio agent entry

Read [START.md](START.md), then [the operating entry](skills/build-bpc-proposals/SKILL.md). This is a portable repository, not an installed personal skill. Apply only the user's current task. A request for a complete proposal authorizes its local writing, modeling, production, review and repair; continue to a finished result. A paragraph request stays a paragraph request.

## Authority

1. Host instructions and truthful handling of sources, results and authorization.
2. The user's current request defines scope, language choices and protected decisions. Current official competition rules define compliance. If the user asks for a departure, explain it and do not certify that version as compliant.
3. Latest accepted project files, guidebook clarifications and documented decisions; resolve conflicting current inputs explicitly.
4. The active BPC manual and task modules below.
5. Reference examples, historical conventions and frameworks as optional craft evidence.

Default proposal language is Indonesian, including when the surrounding chat is English unless the requested proposal language differs. Discuss in the user's language. Support English naturally when requested.

## The governing writing choice

**Sell the developed business.** Let the reader picture its customer experience, offer, purchase, revenue, fulfillment, repeat use and expansion. Describe adopted design directly: “Pelanggan memilih…”, “Perusahaan memperoleh pendapatan melalui…”, “Pesanan diteruskan kepada…”. Present a coherent intended operation without inventing historical events. A designed partner role is different from a signed agreement; a forecast is different from actual sales.

Detailed claim states and assumption checks belong in working records. Keep a material financial assumption beside the result it governs, but remove repetitive maturity warnings, apology paragraphs and conclusions that end at an indefinite pilot. The main proposal must remain a connected commercial argument with appendices closed.

## Reading and routing

Read the [BPC manual](skills/build-bpc-proposals/references/bpc-manual.md) in full on first substantive use; it resolves inherited master conflicts. For prose work read [commercial writing](skills/build-bpc-proposals/references/commercial-writing.md). Then load only the modules needed by the actual task. Read current supplied task documents through available content, inspect meaningful diagrams/tables and record exact gaps. Extraction and inventories do not prove comprehension. Historical corpus learning is indexed in [reading routes](library/reading-routes.md); future narrow tasks need selected lessons, not all PDFs.

Run `python studio.py doctor` before production and follow [setup](docs/setup.md). Never claim a compile, render, research check, independent review or test that did not run. Render the exact final document, inspect its actual pages, reconcile economics separately and repair meaningful defects.

Keep project facts in the project's record, not this reusable guidance. Preserve accepted decisions and protected content. Archive documents and `cases/jejakbalik/` are background, never authorities for a fresh venture. Do not import their names, prices, markets, surveys, approvals, palettes, dates, budgets or page limits.

No loading, cloning or local production request authorizes publication, submission, partner contact or personal-skill installation. This repository performs no external publication automatically.
